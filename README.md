# Голосовой ассистент для задач, встреч и напоминаний

Веб-прототип: говорите или пишете фразу, ассистент создаёт задачу, встречу или напоминание, показывает список на период, ищет записи, переносит, завершает и удаляет их. Ассистент говорит по-русски и переспрашивает, если чего-то не хватает.

Репозиторий: https://github.com/MozzarellaCheesee/MlAssistant. Прототип запускается локально, инструкция ниже.

Документация:

  - [Домен и диалог](docs/domain-and-dialog.md): записи, даты, повторы, `AssistantService`, уточняющие вопросы, интенты
  - [Обработчики команд](docs/command-handlers.md): создание, список, поиск, перенос, завершение, удаление

## Примеры фраз

Фразы произвольные, списков команд нет. Вот что проверено:

- Создать: «Напомни мне завтра в 10 утра позвонить Ивану», «В пятницу нужно отправить отчёт», «Добавь встречу с командой завтра в 15:00», «В четверг в 11 у меня встреча с дизайнером».
- Показать: «Что у меня сегодня?», «Какие задачи у меня на завтра?», «Что запланировано на эту неделю?».
- Найти: «Найди задачу про презентацию», «Когда у меня была встреча с Иваном?».
- Перенести, завершить, удалить: «Перенеси встречу с дизайнером на пятницу», «Отметь её выполненной», «Удали задачу про отчёт».
- Повтор: «Каждый понедельник в 10 планёрка», «Оплатить интернет 15 числа каждого месяца».
- Составные фразы, до 10 команд: «Купить хлеб завтра, напомни в субботу в 10 позвонить маме и поставь встречу с Олегом в понедельник в 15».
- Ссылки на прошлую запись: «Поставь созвон в это же время», «Напомни за час до неё», «Перенеси её на час позже».
- Голос: «Джарвис, что у меня сегодня?» (нужен голосовой режим, см. ниже).
- Недостающее ассистент спрашивает: «Поставь встречу с Иваном завтра» → «На какое время поставить встречу?».

## Требования

- Python 3.12+
- ffmpeg (декодирует загруженное аудио)
- PipeWire (`pw-record`, `pw-play`) или ALSA (`arecord`, `aplay`): нужны только для голосового режима «Джарвис»
- ключ GigaChat API
- приложение на oauth.yandex.ru (нужно для входа; без него работает режим `AUTH_DISABLED=1`)

## Установка и запуск

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # заполните переменные
python -m scripts.pin_certs     # обновить сертификаты GigaChat, если истекли
python -m scripts.import_csv    # загрузить data/voice_assistant_events_1000.csv (пользователю default)
uvicorn --factory app.main:create
```

Быстрый запуск без регистрации приложения в Яндексе: в `.env` поставьте `AUTH_DISABLED=1` и `COOKIE_SECURE=0`. Входа не будет, все работают как пользователь `default` и видят записи из CSV.

Импорт кладёт записи пользователю `default`. При включённом входе (по умолчанию) вошедший пользователь их не увидит: они видны только с `AUTH_DISABLED=1`. Для демо со входом поставьте `DEMO_SEED=1` (он стоит в `.env.example`): демо-записи загрузятся каждому новому пользователю при первом входе.

Названия моделей обязательны, в `.env.example` заданы `GigaChat-2-Pro` и `GigaChat-2`. Список доступных моделей печатает `.venv/bin/pytest -m llm -k live_ping -s`.

Docker:

```bash
docker compose up --build
```

База лежит в томе `data`: записи, история чата и сессии переживают перезапуск и пересоздание контейнера. `docker-compose.yml` сам задаёт `DB_PATH=/data/assistant.db` и перекрывает `DB_PATH=./assistant.db` из `.env`. Раньше при `docker run --env-file .env` база оказывалась в `/app` и пропадала вместе с контейнером.

Модель распознавания речи и e5 скачиваются при сборке и входят в образ. Модель озвучки Vosk скачивается при первом запуске в том `vosk`, повторно не качается.

Джарвис в контейнере (только Linux с PulseAudio или PipeWire):

```bash
docker compose -f docker-compose.yml -f docker-compose.voice.yml up --build
```

Контейнер берёт микрофон и динамики хоста через сокет `$XDG_RUNTIME_DIR/pulse/native`. Внутри `arecord` и `aplay` работают через ALSA-плагин pulse и попадают в звуковой сервер хоста. Режим включается сразу (`VOICE_ENABLED=1`). Со входом через Яндекс задайте `VOICE_USER_ID` своим id, иначе Джарвис пишет записи пользователю `default`. На macOS и Windows сокета нет, там работает только базовый файл. При старте контейнер импортирует CSV пользователю `default`, только если таблица `items` пуста (`--if-empty`). Со входом эти записи не видны, для демо задайте `DEMO_SEED=1`.

| `DB_PATH` | путь к SQLite, по умолчанию `./assistant.db` |
| `STT_MODEL` | модель распознавания речи, по умолчанию `gigaam-v3-e2e-rnnt` |
| `AUTH_DISABLED` | `1` отключает вход, все работают как пользователь `default`; по умолчанию вход включён |

| `VOICE_USER_ID` | id пользователя, которому слушает микрофон; по умолчанию `default` |
| `VOICE_PHRASE_PAUSE_SECONDS` | тишина, после которой фраза считается законченной; по умолчанию `1.0` |
| `VOICE_SESSION_SILENCE_SECONDS` | сколько после ответа можно говорить без имени; по умолчанию `5` |

Значения по умолчанию взяты из `app/config.py`. Переменные без пометки «обязательна» можно не задавать. Громкости ограничиваются диапазоном 0..1. Пример файла: `.env.example`.

## Архитектура

Подробно по каждому модулю: [справочник по коду](docs/README.md).

Слои: домен и сценарии не знают про FastAPI, GigaChat и SQLite (это проверяет `tests/unit/test_architecture.py`).

```
браузер ── HTTP ──> adapters/inbound/http (FastAPI, роутеры по областям)
                         │ вход: AuthService ──> YandexIdProvider (oauth.yandex.ru)
                         │                   └─> SqliteUserStore (users, auth_sessions, oauth_states)
                         │ текст или аудио
                         v
          application: AssistantService ── диалог (черновик, уточнения)
            │ STT (GigaAM)  │ IntentParser: деление фразы (GigaChat Lite), разбор (GigaChat Pro)
            v               v
          обработчики интентов ──> domain (Item, даты)
            │                          
            v                          
   SQLite + items_vec  <──  поиск ──> E5Embedder (ONNX)
```

Разбор команды. Правила лежат в схеме функций: описания полей и примеры (`app/adapters/outbound/gigachat/prompts.py`; снимок схемы проверяет `tests/unit/test_prompt_snapshot.py`). Системный промпт короткий: текущее время с днём недели, ожидаемый вопрос и последние записи. Схема и примеры не меняются от запроса к запросу: в примерах нет конкретных дат. Списков ключевых слов для интентов нет. В лог на уровне INFO пишется имя вызванной функции и список заполненных полей. Значения полей (названия, запросы) попадают в лог только на уровне DEBUG: это слова пользователя.

Логирование сквозное (`app/adapters/observability.py`). Middleware в HTTP-адаптере даёт каждому запросу id (берёт заголовок `X-Request-ID` или создаёт свой, возвращает его в ответе) и пишет строку «метод путь статус длительность». Id попадает в каждую строку лога этого запроса. Порты LLM, STT, TTS и календаря обёрнуты в `bootstrap.py` и `main.py` декоратором `Logged`: он пишет имя вызова, длительность и итог без значений (тип интента, длину текста), а при ошибке её тип. Адаптеры и ядро для этого не меняются. Голосовой цикл «Джарвис» идёт не через HTTP, поэтому id запроса у его строк нет (`-`).

Даты модель не вычисляет. Она переводит слова в короткое выражение, а календарную дату считает код (`app/domain/dates.py`):

| Фраза | Выражение |
|---|---|
| сегодня, завтра, через 3 дня | `today`, `+1d`, `+3d` |
| через неделю, через месяц | `+1w`, `+1m` |
| в пятницу | `fri`, ближайшая пятница после сегодня |
| в среду на следующей неделе | `next wed` |
| до конца недели, до конца месяца | `eow`, `eom` |
| 15 декабря | `12-15`, ближайшее такое число не в прошлом |
| на этой неделе, в следующем месяце (период списка) | `week`, `next month` |

«Через месяц» от 31 января даёт 28 или 29 февраля. Непонятное выражение отбрасывается, и ассистент переспрашивает дату.

Модель возвращает рядом с временем и датой дословные куски фразы: `time_said` и `date_said`. Если такого куска во фразе нет, время или дата отбрасываются, и ассистент спрашивает. Так модель не подставит полночь вместо «время не названо». Проверка не применяется, когда пользователь отвечает на вопрос ассистента, и к дате повторяющейся записи.

Поток: аудио, GigaAM, текст, деление на команды (GigaChat Lite), разбор каждой команды (GigaChat Pro, function calling), обработчик, SQLite и календарь, ответ текстом и голосом. Аудио со страницы проходит через ffmpeg, звук с микрофона компьютера идёт в GigaAM напрямую. GigaChat возвращает выражение даты, время (H:MM, как сказано) и правило повтора (подмножество RFC 5545, RRULE). Код переводит выражение в дату, проверяет формат и невозможное время, не даёт создать запись в прошлом и ищет конфликты.

## Технологии

- FastAPI и uvicorn: небольшой HTTP-слой с загрузкой файлов.
- GigaAM (onnx-asr): русское распознавание речи, работает локально на CPU.
- GigaChat: разбор команды через function calling, в том числе даты и повторы. Модель вызывает одну из функций: `create_item` (с полем `kind`: задача, напоминание, встреча), `list_items`, `search_items`, `update_item`, `complete_item`, `delete_item`, `confirm`. Адрес API закреплён: `base_url` https://gigachat.devices.sberbank.ru/api/v1, адрес по умолчанию из SDK (api.giga.chat) не используется. При ответе 429 запрос повторяется дважды, через 1 и 2 секунды.
- SQLite: один файл, векторы записей лежат в таблице `items_vec`. Сервер держит одно соединение и один общий lock (`app/adapters/outbound/sqlite/db.py`), запросы к базе идут по очереди. Для прототипа этого хватает. При росте нагрузки понадобится пул соединений или отдельная СУБД.
- intfloat/multilingual-e5-small: эмбеддинги запросов и записей, ONNX-модель через onnxruntime и tokenizers, работает локально на CPU. Модель скачивается при сборке Docker-образа.
- Vosk TTS (`vosk-tts`): синтез речи, работает локально на CPU.

## Поиск

Поиск смысловой. Название и описание записи превращаются в вектор моделью e5, запрос тоже. Векторы считаются при создании и изменении записи, недостающие досчитываются при старте.

Запись попадает в выдачу, если проходит два порога. Косинусная близость запроса не ниже 0,80. И либо близость запроса без служебных слов («найди», «встреча», «задача», «созвон», «про», «с») не ниже 0,88, либо у запроса и названия есть общая основа (первые пять букв слова, «Иван» совпадёт с «Иваном»). Без проверки основы бессмысленный запрос находил бы записи только по близости векторов.

Фильтр по типу ставит модель в поле `kind`, поиск его применяет. Фильтр «задача» включает и напоминания (`ItemKind.matches`), так в списке задач напоминание тоже видно.

Опечатки не исправляются. Слово с опечаткой в первых пяти буквах не даст общей основы, а близость векторов может не дотянуть до 0,88.

## Повторяющиеся записи

Повтор можно назвать в команде для задачи или встречи: «каждый день», «ежедневно», «по будням», «по выходным», «каждый понедельник», «по понедельникам и средам», «каждую неделю», «каждые две недели», «каждые 2 недели по понедельникам», «каждый месяц», «каждое 15 число», «15 числа каждого месяца», «каждый год». Подходит и «каждые N дней, недель, месяцев, лет».

Серия хранится одной строкой в `items`. Правило записано подмножеством RRULE: `FREQ` (DAILY, WEEKLY, MONTHLY, YEARLY), `INTERVAL`, `BYDAY` для недель, `BYMONTHDAY` от 1 до 31 для месяцев. Вхождения разворачивает репозиторий: для списков, проверки конфликтов и поиска напоминаний. Правила пишет GigaChat, но принимаются только эти поля: `validate_rrule` отвергает остальное, поэтому своего разворота хватает и `dateutil` не нужен. Перебор ограничен 3660 днями, диапазон в `/api/items` не больше 366 дней.

Первое вхождение: ближайшая дата по правилу от названной даты или от сегодня. Если дату не назвали и время сегодня уже прошло, берётся следующая подходящая по правилу дата, не обязательно завтрашняя. Проверка «в прошлом» к сериям не применяется. Конфликт проверяется на первом вхождении, существующие серии в проверке участвуют.

Напоминание срабатывает один раз на каждое вхождение. Пропущенные вхождения сливаются в одно срабатывание.

Завершить, удалить или перенести серию можно по-разному, поэтому ассистент спрашивает: «Это повторяющаяся запись (правило). Изменить только ближайшее повторение (дата) или все?»
- «Только ближайшее»: дата попадает в `exdates`. При переносе создаётся отдельная обычная запись на новые дату и время. Так происходит и при простой смене названия.
- «Все»: вся серия получает статус `done` или `cancelled`.

Целую серию на другой день перенести нельзя, ассистент откажет. Для всех повторов меняются только время и название, в том числе сдвигом «на час позже». Перенос записи в прошлое и на время другой встречи ассистент подтверждает так же, как при создании.

Если в ближайшие 400 дней вхождений не осталось, вопрос не задаётся. Если уточнения нет или выбрано «все», ассистент работает со всей серией. Если выбрано «только ближайшее», он отвечает: «У этой серии больше нет повторений.»

Запрос только по типу («найди созвон») возвращает записи этого типа, отсортированные по расстоянию даты от сегодня, прошедшие тоже. У серии берётся дата первого вхождения.

## Голосовой режим «Джарвис»

Сервер слушает микрофон компьютера, на котором запущен. Для записи используется `pw-record`, если его нет, то `arecord`. В Docker режим работает через звуковой сервер хоста, см. «Установка и запуск».

- Команда начинается с имени (`WAKE_WORD`, по умолчанию «Джарвис»). Ассистент отвечает «Слушаю» и сигналом.
- Фраза заканчивается после `VOICE_PHRASE_PAUSE_SECONDS` тишины.
- После ответа можно говорить без имени, пока тишина короче `VOICE_SESSION_SILENCE_SECONDS`.
- Раннее распознавание: после 0,5 с тишины распознавание стартует заранее, не дожидаясь конца паузы. Если пользователь продолжил, результат отбрасывается.
- WAV из голосового цикла (16 кГц, моно) идёт в распознавание без ffmpeg, это экономит около 110 мс.
- Слова-паразиты («э», «эм», «ну») вырезаются из фразы.
- Пока ассистент говорит, запись прерывается: он не слышит сам себя.
- Фразы без имени вне разговора игнорируются и не попадают в чат.
- Наступившие напоминания голосовой цикл проверяет каждые 30 секунд, произносит и пишет в чат.
- Сигналы (`VOICE_SOUNDS`) имеют свою громкость `VOICE_BEEP_VOLUME`, речь `VOICE_VOLUME`.
- Голос: Vosk `vosk-model-tts-ru-0.9-multi`, голос `TTS_SPEAKER` (по умолчанию 4, мужской). Модель скачивается при первом запуске и грузится около минуты. С `TTS_PRELOAD=1` загрузка идёт в фоне при старте.
- `VOICE_ENABLED=1` включает режим при старте. Иначе его включает переключатель «Джарвис» на странице.
- Включать и выключать режим может только владелец, `VOICE_USER_ID`. Это должен быть id вошедшего пользователя: «u» + Яндекс uid. Узнать его: `sqlite3 assistant.db "select id from users"`. Без входа (`AUTH_DISABLED=1`) подходит `default`.
- Пока режим включён, режим без рук на странице владельца не работает: сервер отвечает «Джарвис уже слушает микрофон компьютера».
- `VOICE_DEBUG=1` пишет в лог тексты распознанных фраз. По умолчанию выключено: распознанная речь приватна.

## Веб-страница

- Чат с историей на сервере: страница показывает последние 50 сообщений и каждые 1,5 секунды подтягивает новые, в том числе сказанные голосом на компьютере.
- Боковая панель «Сегодня» и «Завтра» со списком записей. На узком экране открывается кнопкой.
- В боковой панели записи можно добавлять, менять и удалять руками: кнопка «+» у дня, щелчок по строке открывает форму с полями вид, название, дата, время и длительность встречи. Чат при этом не затрагивается.
- Иконки SVG вместо эмодзи, светлая и тёмная темы по настройке системы.
- Настройки: громкость речи, громкость сигнала, переключатель «Озвучивать ответы», переключатель «Джарвис».
- Кнопка микрофона с кольцом состояния: ожидание, слушаю, думаю, отвечаю, ошибка. Нажатие включает режим без рук: страница слушает микрофон браузера и реагирует на имя. Запись одного сообщения тоже есть.
- Ответ на голосовое сообщение со страницы озвучивается тем же голосом Vosk, если озвучка включена. Если сервер озвучить не может, говорит браузер.
- Страница раз в 30 секунд спрашивает у сервера наступившие напоминания и показывает их.

## Вход через Яндекс ID

1. На oauth.yandex.ru создайте приложение с платформой «Веб-сервисы».
2. В правах отметьте доступ к логину, к адресу почты (`login:email`) и к календарю (`calendar:all`). Адрес и календарь нужны только для выгрузки в Яндекс Календарь.
3. В Redirect URI укажите `http://localhost:8000/auth/callback`. Для другого адреса поменяйте и `YANDEX_REDIRECT_URI`.
4. Скопируйте ID и пароль приложения в `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`.
5. При запуске по http без TLS поставьте `COOKIE_SECURE=0`: с флагом `Secure` браузер не вернёт cookie.

Без входа открывается экран с кнопкой «Войти через Яндекс». Если вход не удался, на этом экране появится сообщение об ошибке. Кнопка «Выйти» удаляет сессию. Для локальной разработки поставьте `AUTH_DISABLED=1`: экран входа и кнопка выхода пропадают, а `/api/me` отвечает «Гость».

После входа сервер выдаёт случайный токен в cookie `sid` (`HttpOnly`, `SameSite=Lax`, `Secure` по умолчанию, срок 30 дней). В базе лежит только его sha256, поэтому по утечке базы сессию не подделать. Токен Яндекса уходит только в заголовке `Authorization`. Без `TOKEN_ENCRYPTION_KEY` он не хранится, с ключом сохраняется в зашифрованном виде для выгрузки в календарь.

Против login CSRF при старте входа сервер ставит cookie `oauth_state` (`HttpOnly`, `SameSite=Lax`, путь `/auth`, 10 минут) и передаёт то же значение в `state`. Значения `state` лежат в таблице `oauth_states`. Callback сверяет cookie с `state` и принимает вход, только если `state` не использован и не просрочен. Просроченные `state` и сессии удаляются при создании новых. Новый вход отзывает прежнюю сессию этого браузера.

Пользователь получает идентификатор `u` + Яндекс uid. Все записи, поиск и напоминания фильтруются по нему, ключ диалога составляется из пользователя и `session_id`, поэтому данные одного человека другому не видны. Старые записи остались у `default`.

С `DEMO_SEED=1` при первом входе в аккаунт загружается `data/voice_assistant_events_1000.csv`. Ошибка загрузки только пишется в лог, вход не ломается.

## Яндекс Календарь

Встречи и напоминания со временем записываются в основной календарь пользователя в Яндексе по CalDAV. Серии уходят одним событием с правилом повтора, пропущенные повторения как исключения. Встреча занимает свою длительность (по умолчанию час), напоминание 15 минут и срабатывает сигналом в момент начала. Задачи и записи без времени не выгружаются. Перенос и переименование перезаписывают то же событие, удаление его удаляет. Отметка «выполнено» календарь не трогает. Исключение: выполненное одно повторение серии уходит в календарь как исключение, и событие этого дня пропадает.

Выгрузка идёт в одну сторону: из ассистента в календарь. Правки в самом календаре ассистент не видит.

Настройка:

1. В правах приложения на oauth.yandex.ru отметьте `login:email` и `calendar:all`.
2. Создайте ключ и впишите его в `.env` как `TOKEN_ENCRYPTION_KEY`: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`.
3. Войдите заново: токен и адрес почты сохраняются при каждом входе. Рядом с именем появится «Календарь подключён».

Токены лежат в таблице `calendar_links` в зашифрованном виде (Fernet), ключ только в `.env`. Просроченный токен обновляется по `refresh_token`. Выгрузка выключена без ключа и при `AUTH_DISABLED=1`. Если календарь недоступен, запись всё равно сохраняется, а к ответу добавляется «Запись сохранена, но в календарь не попала.»

## TLS и сертификаты

Серверы GigaChat подписаны «Russian Trusted Sub CA» Минцифры. Корневой сертификат Минцифры мы не устанавливаем, а `verify_ssl_certs=False` не используем. Вместо этого два листовых сертификата (ngw.devices.sberbank.ru:9443 и gigachat.devices.sberbank.ru:443) лежат в `certs/gigachat.pem` и доверенными считаются только в SSLContext клиента GigaChat (`VERIFY_X509_PARTIAL_CHAIN`). Другие сайты этим контекстом отклоняются, проверено на ya.ru.

Сертификаты истекают 30.06.2027 и 13.07.2027. Обновление: `python -m scripts.pin_certs`.

## Технические решения

Многие решения появились после ошибок на живом GigaChat или в диалогах с ассистентом, рядом с ними написано, что ломалось. Слабые места перечислены в разделе «Ограничения и что дальше».

### Стек

| Задача | Выбор | Почему | Почему не очевидная альтернатива |
|---|---|---|---|
| Понять команду | GigaChat Pro, function calling | Понимает русский, доступен из России, ключ выдан в задании. Function calling возвращает поля по схеме, их проверяет pydantic | Ключевые слова и регулярные выражения ломаются на перефразировании, заказчик их запретил. Своему классификатору нужны размеченные данные |
| Разделить фразу на команды | GigaChat Lite | Точность как у Pro (19 из 19), ответ за 0,34 с вместо 0,71 с | Pro вдвое медленнее на той же задаче |
| Распознать речь | GigaAM v3 через onnx-asr | Обучена на русском, работает на CPU. Фраза длиной 3-4 с распознаётся примерно за 0,2 с, голос не уходит с компьютера | Облачное распознавание отправляет голос третьей стороне и добавляет сеть к задержке |
| Озвучить ответ | Vosk TTS | Бесплатный, работает на CPU, короткий ответ синтезирует за 0,2-0,6 с | Голос браузера зависит от ОС. Он остался запасным, если сервер озвучить не может |
| Искать по смыслу | multilingual-e5-small в ONNX | ТЗ требует находить записи по близким по смыслу запросам. Модель маленькая, многоязычная, работает на CPU | Полнотекстовый поиск находит только совпадающие слова |

### Архитектура: порты и адаптеры

ТЗ отдельно оценивает, насколько разделены голос, LLM, бизнес-логика и хранение. Поэтому проект построен по гексагональной схеме. Домен (`app/domain`) и сценарии (`app/application`) общаются с внешним миром только через порты в `app/application/ports`. GigaChat, SQLite, GigaAM, Vosk и CalDAV подключены адаптерами в `app/adapters`, связывает их `app/bootstrap.py`.

Что это даёт:

- GigaChat или SQLite меняются заменой адаптера, логика не трогается. `tests/unit/test_architecture.py` падает, если ядро импортирует FastAPI, GigaChat, SQLite или другую инфраструктуру.
- Сценарии тестируются с фейками портов, без сети и моделей. Время приходит из порта `Clock`, поэтому тесты не зависят от реальной даты.
- Логирование добавлено без правки адаптеров. Декоратор `Logged` оборачивает порты и пишет имя вызова, длительность и итог.

Цена: больше файлов и слой портов, которых в прототипе на одном модуле не было бы.

Каждому интенту соответствует свой обработчик в `app/application/handlers`. Интенты описаны pydantic-моделями с полем-дискриминатором `intent`. Тест проверяет, что у каждого интента есть обработчик. Форма в боковой панели вызывает те же обработчики, что и чат, поэтому проверка времени, поиск и выгрузка в календарь одинаковы для голоса, текста и формы.

### Понимание запроса

Модель хорошо понимает, что человек имел в виду, и ошибается в календарной арифметике. Поэтому она переводит слова в поля и короткие выражения, а даты, время и проверки считает код.

- Списков ключевых слов нет. Ранние проверки по словам ошибочно срабатывали на ответах пользователя на уточняющий вопрос. Отказ от ключевых слов также требование заказчика.
- Одна функция `create_item` с полем `kind` вместо трёх функций для задачи, напоминания и встречи. С тремя функциями модель путала тип: «Купить билеты в театр до конца недели» становилось встречей. С одной функцией живая проверка выросла с 43 до 45 фраз из 46.
- Правила лежат в описаниях полей и функций, системный промпт короткий. С длинным блоком правил в промпте модель на «Напомни купить молоко» выбирала удаление или отметку о выполнении. После переноса правил в схему проверка дала 46 из 46.
- Дату по календарю считает код. Модель видела календарь на 14 дней и дальше ошибалась на «через месяц» и «в следующем месяце». Теперь она отдаёт выражение (`+1m`, `next wed`), а дату считает `app/domain/dates.py`.
- Время модель передаёт так, как его сказали, проверяет его код. Модель молча заменяла невозможное время («завтра в 29 часов») правдоподобным. Теперь ассистент отвечает «Такого времени нет. Во сколько?».
- Вместе с датой и временем модель возвращает кусок фразы, где они названы (`time_said`, `date_said`). Если куска во фразе нет, значение отбрасывается и ассистент переспрашивает. На «Напомни завтра позвонить в банк» модель сама ставила 00:00 или 23:59, и ни описание поля, ни примеры её не останавливали.
- Ссылки на другую запись модель отмечает флагами: `same_day`, `same_time`, `offset_minutes`, `offset_days`. Дату и время считает код. На наборе из 15 таких фраз было 5 верных разборов, стало 14.
- Сдвиг записи («на час позже», «на день раньше») модель отдаёт в `delay_minutes`, `delay_days` и `delay_months`, код считает от времени самой записи. Раньше «на следующий день» отсчитывалось от сегодня.
- В примерах схемы нет конкретных дат, только выражения. Схема не меняется от запроса к запросу, её снимок проверяет `tests/unit/test_prompt_snapshot.py`.
- «В пятницу», сказанное в пятницу, означает следующую пятницу. Час без «утра» или «вечера» с 8 до 11 считается утром, с 1 до 7 к нему прибавляется 12. Так обычно говорят люди.

### Составные фразы

- Фразу на команды делит отдельный запрос к модели. В общем разборе модель теряла вторую команду после запятой или «потом». Отдельный запрос дал 38 верных ответов из 38 на 19 фразах в двух прогонах. Делить по «и» и запятым кодом нельзя: «встреча с Иваном и Петром» одна команда.
- Деление и разбор идут по очереди. Личный тариф GigaChat отвечает 429 на второй одновременный запрос, параллельный ход занимал 3,2-4,4 с.
- В одной фразе не больше 10 команд. Это требование заказчика и защита от бесконечной цепочки.
- Если команда в цепочке задаёт вопрос, остальные ждут ответа в черновике и выполняются после него.
- Команда без даты берёт день предыдущей: «купить хлеб послезавтра и в 10 позвонить маме» ставит оба дела на послезавтра.

### Диалог

- Вопрос ассистента живёт 10 минут (`DIALOG_PENDING_TTL_SECONDS`). Без срока забытый вопрос перехватывал не связанную с ним фразу.
- «Да» считается подтверждением, только если ассистент задал вопрос-подтверждение. Иначе на «почему голос женский?» ассистент отвечал «Хорошо.».
- На вопрос о пересечении встреч можно назвать другое время. Новое время проверяется заново.
- Если запись для «удали» или «отметь» не найдена, ассистент предлагает создать задачу. Модель иногда принимает новое дело за удаление, так фраза не теряется и ничего лишнего не удаляется.
- «Напомни о встрече в 9» создаёт отдельное напоминание и не переносит встречу.
- Удаление ставит статус `cancelled` и оставляет запись в базе. История сохраняется, а «её» в следующей фразе пропускает отменённые записи.
- Ответ на уточняющий вопрос уходит в модель вместе с черновиком. Без модели разбираются только точные «да», «нет» и номер из списка: словари ошибались на «да нет» и «не знаю».

### Поиск

- Запись попадает в выдачу через два порога. Близость запроса не ниже 0,80, и либо близость без служебных слов не ниже 0,88, либо общая основа слова (первые пять букв). Бессмысленный запрос получал от e5 близость около 0,83, поэтому одного порога мало. Запрос из одного имени получал низкую близость, его находит общая основа: «Иван» совпадает с «Иваном».
- Служебные слова («найди», «встреча», «задача») перевешивали смысл: «встреча с Иннокентием» находила встречи с Анной. Для второго порога они убираются из запроса.
- Тип записи в поиске задаёт модель полем `kind`.
- Векторы ищутся полным перебором с матричным умножением. По оценке, этого хватает примерно до 100 тысяч записей, дальше нужен ANN-индекс.

### Голос

- Сервер сам слушает микрофон компьютера и реагирует на имя «Джарвис» (`WAKE_WORD`). Страницу открывать не нужно, как с Алисой.
- Фраза заканчивается после 1,0 с тишины. С 1,5 с ответ ощущался запоздалым.
- Распознавание начинается после 0,5 с тишины. Если человек продолжил, результат выбрасывается. Если замолчал, текст готов к концу паузы.
- Звук с микрофона идёт в GigaAM без ffmpeg: он уже в нужном формате. Подготовка звука занимает 0,1 мс вместо 110 мс. Аудио из браузера идёт через ffmpeg.
- Пока Джарвис говорит, запись прерывается и запускается заново через 0,15 с после ответа. Так он не слышит себя и не теряет ответ пользователя, сказанный сразу после вопроса.
- Модель синтеза грузится около минуты, поэтому загрузка идёт в фоне при старте сервера.
- Наступившие напоминания произносит Джарвис, страница их только показывает. Когда страница и Джарвис забирали напоминания одновременно, часть их терялась.
- Распознанные фразы не пишутся в лог без `VOICE_DEBUG=1`: разговоры у микрофона приватны.

### Безопасность и вход

- Сертификаты GigaChat закреплены: два листовых сертификата лежат в `certs/gigachat.pem` и доверенными считаются только в клиенте GigaChat. Корневой сертификат Минцифры дал бы доверие ко всем сайтам, которые он подписывает. Отключённая проверка (`verify_ssl_certs=False`) открыла бы подмену ответа.
- Вход через Яндекс ID: пароли не хранятся, а тот же вход даёт доступ к календарю.
- В базе лежит sha256 от токена сессии. По утечке базы сессию не подделать.
- Значение `state` при входе сверяется с cookie `oauth_state`. Это защищает от login CSRF.
- Включить голосовой режим может только владелец (`VOICE_USER_ID`). Микрофон у компьютера один.
- ffmpeg запускается с `-protocol_whitelist pipe` и `-t 31`, файлы больше 2 МБ отклоняются. Текст запроса в SQL не попадает: поиск идёт по векторам.

### Яндекс Календарь

- Выгрузка идёт по CalDAV с заголовком `Authorization: OAuth <токен>`. Так описано в документации Яндекс 360, пароль приложения не нужен.
- Выгрузка односторонняя. Обратная синхронизация не входила в задачу и требует разрешать конфликты правок.
- Если календарь не подключён, выгрузка пропускается без сообщения. Если календарь недоступен, запись сохраняется, а ассистент предупреждает об этом.

### Данные

- CSV из задания импортируется по первому слову названия: «Встреча», «Созвон», «Демо», «планёрка» дают встречу, «Напомнить» даёт напоминание, остальное становится задачей. Повторный импорт не создаёт дублей.
- Сервер держит одно соединение с SQLite и один общий lock, запросы идут по очереди. Для прототипа хватает. При росте нагрузки нужен пул соединений или отдельная СУБД.

## Качество

Тесты запускаются командой `.venv/bin/pytest -q`. Стиль кода проверяет ruff (настройки в `pyproject.toml`): `pip install -r requirements-dev.txt`, затем `.venv/bin/ruff check app scripts`. 11 тестов отключены маркерами `llm` и `model`: им нужны ключ или скачанные модели. Время в тестах подставное: код берёт «сейчас» только из порта `Clock`, поэтому результат не зависит от реальной даты.

- `tests/unit`: домен (даты, повторы, имя ассистента и слова-паразиты), адаптеры (SQLite, e5, GigaChat с подменой SDK, CalDAV, ICS, Yandex ID), вход и сессии, голосовой цикл, HTTP, и `test_architecture.py`, который запрещает слоям импортировать лишнее.
- `tests/scenarios`: сценарии через `AssistantService` с фейками: создание, список и поиск, перенос и удаление, повторы, календарь, изоляция пользователей.
- `tests/llm_eval`: живая проверка GigaChat.

### Живая проверка llm_eval

Проверка на реальном GigaChat: 57 фраз, порог 0,9. Сверяются интент и поля: дата, время, период, новая дата, сдвиги. Ожидаемые даты записаны выражениями и считаются от времени теста, поэтому не устаревают. Есть фразы дальше двух недель: «через месяц», «15 декабря», «в следующем месяце», «в среду на следующей неделе». Последний прогон: 57 из 57.

```bash
.venv/bin/pytest -m llm tests/llm_eval -s
```

Ключ берётся из `.env`. Без `GIGACHAT_CREDENTIALS` тест пропускается. По той же причине пропускается `test_live_ping`: он ходит в настоящий API.

## Ограничения и что дальше

- Голос слушает микрофон одного компьютера, владелец один (`VOICE_USER_ID`). В Docker Джарвис работает только на Linux-хосте со звуковым сервером.
- Часовой пояс один на всех: Europe/Moscow.
- «В пятницу через три недели» (день недели плюс сдвиг) выражения дат не поддерживают.
- Сертификаты GigaChat закреплены листовые: после их перевыпуска нужно запустить `python -m scripts.pin_certs`.
- Календарь односторонний: правки в Яндекс Календаре ассистент не видит.
- Опечатки в поиске не исправляются.
- Личный тариф GigaChat отвечает 429 на параллельные запросы, поэтому команды цепочки идут по очереди и составная фраза отвечает дольше.
- Вход только через Яндекс ID, выход завершает только текущую сессию.
- Эндпоинты с cookie не проверяют заголовок Origin, защита от CSRF только через `SameSite=Lax`. `/api/reminders/due` изменяет состояние, поэтому это POST.
- Дальше: потоковое распознавание речи, исправление опечаток, чтение событий из календаря, развёртывание на сервере с HTTPS.
