## 2. HTTP-адаптер `app/adapters/inbound/http/`

Пакет разбит по областям. Каждый модуль отдаёт функцию, которая строит `APIRouter`:

| Модуль | Роутер | Маршруты |
|---|---|---|
| `http/chat.py` | `chat_router` | `/api/message`, `/api/audio`, `/api/history` |
| `http/items.py` | `items_router` | `/api/items`, `/api/items/{id}`, `/api/reminders/due` |
| `http/voice.py` | `voice_router` | `/api/voice`, `/api/listen` |
| `http/speech.py` | `speech_router` | `/api/speech/{id}`, `/api/speak-text` |
| `http/auth.py` | `me_router`, `login_router` | `/api/me`, `/auth/login`, `/auth/callback`, `/auth/logout` |
| `http/common.py` | — | общее: `make_current_user`, `read_audio`, `item_to_dict`, `reply_to_dict`, `MAX_AUDIO` |

Зависимости (`service`, `voice`, `tts`, `clock`) роутеры получают аргументами фабрики и держат в замыкании.

Адаптер собирает функция `create_app` (`http/__init__.py:47`): подключает роутеры, обработчики ошибок (`_add_error_handlers`, `http/__init__.py:93`) и статику. Он получает порт `AssistantPort`, а не конкретный сервис: слой приложения не знает про FastAPI. Проверку этого запрета делает `tests/unit/test_architecture.py`.

### 2.1 Общие правила

Аутентификация. Зависимость `current_user` (`http/common.py:19`, создаёт её `make_current_user`) вызывается почти в каждом эндпоинте.

- Если `auth is None` (вход отключён, `AUTH_DISABLED=1`), она возвращает строку `"default"`.
- Иначе она читает cookie `sid`, ищет пользователя через `auth.user_for` и возвращает `user.id`. Нет пользователя: `AssistantError(UNAUTHORIZED)`, ответ 401.
- Найденный id кладётся в `request.state.user_id`, чтобы лог ошибок знал пользователя. В режиме без входа поле не заполняется.

Исключения: `/api/me` и маршруты `/auth/*` не используют `current_user`. `/api/me` проверяет cookie сам (`http/auth.py:22`).

Формат ответа. Все тела ответов об ошибках имеют вид `{"reply": "<текст для человека>", "error": "<код>"}`. Успешные ответы чата содержат `"error": null` (`reply_to_dict`, `http/common.py:51`).

Обработчики ошибок:

| Исключение | Статус | Тело | Где |
|---|---|---|---|
| `AssistantError` | `HTTP_STATUS[e.code]` | `{"reply": e.user_message, "error": e.code}` плюс `message_ids`, если сервис записал ошибку в историю | `http/__init__.py:95` |
| `RequestValidationError` | 422 | `{"reply": "Не получилось разобрать запрос. Проверьте текст и попробуйте ещё раз.", "error": "bad_request"}` | `http/__init__.py:115` |
| `FormError` | 404 при `not_found`, иначе 422 | `{"reply": e.text, "error": "not_found" \| "bad_request"}` | `http/__init__.py:109` |
| любое другое `Exception` | 500 | `{"reply": "Что-то пошло не так. Попробуйте ещё раз.", "error": "internal"}` | `http/__init__.py:122` |

Статусы кодов `AssistantError` (`HTTP_STATUS`, `http/__init__.py:32`; ядро знает только код и текст, `test_errors.py` проверяет, что статус есть у каждого кода):

| Код | Статус |
|---|---|
| `llm_unavailable`, `llm_quota`, `llm_rate_limit`, `cert_mismatch` | 503 |
| `llm_bad_response`, `stt_empty`, `stt_failed`, `calendar_failed` | 200 |
| `audio_too_long` | 413 |
| `unauthorized` | 401 |
| `auth_failed` | 400 |

Часть ошибок идёт со статусом 200: ответ остаётся в чате обычным сообщением, а поле `error` помечает его для страницы.

Обработчик `AssistantError` пишет предупреждение в лог: `session`, `user`, `code`, `detail`. Текст запроса в лог не попадает.

Неожиданное исключение логируется с трассировкой (`log.error(..., exc_info=e)`), а клиент получает общий текст.

Статика. В конце `create_app` монтируется `StaticFiles(directory=static, html=True)` в корень (`http/__init__.py:73`). Монтирование стоит последним, поэтому маршруты API и `/auth/*` имеют приоритет. `GET /` отдаёт `index.html`. Если `auth is None`, маршруты `/auth/*` не регистрируются.

Журнал запросов. Middleware `_access_log` (`http/__init__.py:77`) ставит id запроса: берёт заголовок `X-Request-ID` (до 32 символов) или создаёт свой, возвращает его в ответе и кладёт в `request_id` из `app/adapters/observability.py`, поэтому id попадает в каждую строку лога этого запроса. В конце пишет строку «метод путь статус длительность»: для `/api` и `/auth` на уровне INFO, для статики на DEBUG.

Жизненный цикл. `lifespan` (`http/__init__.py:57`) ничего не делает при старте. При остановке он вызывает `voice.stop` в пуле потоков, если голос настроен.

### 2.4 Общие функции `http/common.py`

`item_to_dict(item: Item) -> dict` (`http/common.py:38`). Превращает запись в JSON-словарь: `id`, `kind` (строка), `title`, `starts_at`, `ends_at`, `due_date` (ISO-строки или `null`), `status` (строка), `rrule`. Время идёт с часовым поясом так, как его хранит `Item`. Функцию используют `/api/items`, `/api/reminders/due` и `reply_to_dict`.

`reply_to_dict(reply: Reply) -> dict` (`http/common.py:51`). Собирает тело ответа чата: `reply`, `items` (список из `item_to_dict`), `clarify`, `error: null`. Поле `message_ids` добавляется, если оно непустое. Поле `transcript` добавляется, если оно не `None`. Пустая строка в `transcript` тоже попадёт в ответ.

### 2.5 `create_app` и функции внутри роутеров

`create_app(service, auth, cookie_secure=True, voice=None, tts=None, links=None, clock=None) -> FastAPI` (`http/__init__.py:47`).

| Параметр | Назначение |
|---|---|
| `service` | `AssistantPort`: вся логика ассистента |
| `auth` | `AuthService` или `None`. `None` отключает вход |
| `cookie_secure` | Флаг `Secure` для cookie. Из `Settings.cookie_secure` |
| `voice` | `VoiceControl` или `None`. `None`: голос не настроен |
| `tts` | Движок озвучки с методом `synthesize` и необязательным свойством `ready` |
| `links` | `CalendarLinks` или `None`. Нужен для поля `calendar` в `/api/me` |
| `clock` | `Clock`. По умолчанию `SystemClock`. Используется для проверки возраста сообщения в `/api/speech` |

Время берётся из `Clock`, а не из `datetime.now`. Причина: по README весь код получает «сейчас» только из порта `Clock`, поэтому тесты подставляют фиксированное время. (Исключение: `time.monotonic()` в `/api/listen`.)

`lifespan(_)` (`http/__init__.py:57`). Асинхронный менеджер контекста. После `yield` останавливает голосовой цикл.

`current_user(request) -> str` (`http/common.py:19`). Описана в п. 2.1.

`read_audio(file) -> bytes` (`http/common.py:31`). Читает загруженный файл с пределом `MAX_AUDIO`, превышение даёт `AssistantError(AUDIO_TOO_LONG)`, ответ 413.

`with_tts(state: dict) -> dict` (`http/voice.py:42`, внутри `voice_router`). Добавляет к состоянию голоса поле `tts_ready`.

- `ready = tts is None or getattr(tts, "ready", True)`.
- Если голос не настроен (`voice is None`) и движок готов, словарь возвращается без изменений (без `tts_ready`).
- Если голос настроен и движок готов, добавляется `tts_ready: true`.
- Если голос настроен, а движок не готов: при `state` в (`off`, `loading`) и `available` состояние подменяется на `loading` с текстом «загружаю голос… (около минуты при первом запуске)»; в любом случае добавляется `tts_ready: false`.

Подмена нужна, потому что модель Vosk грузится около минуты. Комментарий в коде: «голос грузится, даже если переключатель выключен». Страница по `tts_ready === false` показывает значок загрузки.

#### `POST /api/message` (`http/chat.py:22`)

Один ход диалога текстом.

- Запрос: JSON `MessageIn` (`session_id`, `text`).
- Ответ: тело `reply_to_dict`: `{"reply", "items", "clarify", "error": null, "message_ids"?}`.
- Обработчик синхронный, FastAPI запускает его в пуле потоков.
- `session_id` записывается в `request.state.session_id` для лога ошибок.
- Ключ диалога строится в сервисе из пары «пользователь, сессия», поэтому разные пользователи с одним `session_id` не пересекаются (в сервисе: `f"{user_id}:{session_id}"`).

#### `POST /api/audio` (`http/chat.py:27`)

Одно голосовое сообщение, записанное кнопкой микрофона.

- Запрос: `multipart/form-data`, поля `session_id` (1..100 символов) и `file` (аудио).
- Читает не больше `MAX_AUDIO + 1` байт. Если прочитано больше `MAX_AUDIO`, бросает `AUDIO_TOO_LONG` (413). Так сервер не держит в памяти весь большой файл.
- Распознавание и ход диалога идут в пуле потоков (`run_in_threadpool(service.handle_audio, ...)`).
- Ответ: тело чата. Если есть `message_ids`, добавляется `speak_id`, равный последнему id. Страница по нему запрашивает озвучку через `/api/speech/{id}`. Комментарий в коде: «ответ на голос со страницы: страница озвучивает через /api/speech».
- Поле `transcript` в ответе содержит распознанный текст (его добавляет сервис).

#### `GET /api/history` (`http/chat.py:42`)

- Параметры: `after` (целое >= 0, по умолчанию 0), `limit` (1..200, по умолчанию 100).
- Ответ: список сообщений из `service.history(user, after, limit)`. Элементы содержат `id`, `role`, `text`, `items`, `source`, `created_at` (по использованию на странице и в `/api/speech`; точную форму определяет журнал сообщений).
- Страница опрашивает его каждые 1,5 с и дополняет чат записями, сделанными голосом на компьютере (README, «Веб-страница»).

#### `GET /api/voice` (`http/voice.py:51`)

Состояние голосового режима для страницы. Три случая:

1. Голос не настроен (`voice is None`): `VOICE_OFF` = `{"enabled": false, "state": "off", "detail": "голос не настроен", "wake_word": "", "available": false}` (`http/voice.py:16`).
2. Пользователь — владелец (`user == voice.owner`): `voice.status()`.
3. Пользователь не владелец: словарь `foreign` с `detail` «голосовой режим доступен только владельцу», плюс `wake_word`, `phrase_pause`, `session_silence` и текущие `volume`, `beep_volume`.

Результат проходит через `with_tts`. Неавторизованный вызов даёт 401.

Не-владелец получает `wake_word`, `phrase_pause` и `session_silence`: страница берёт из них имя, паузу и окно разговора для режима без рук (`hfWin`, `hfTick`).

#### `POST /api/voice` (`http/voice.py:59`)

- Запрос: JSON `VoiceIn`.
- Если голос настроен и пользователь не владелец: 403, `{"reply": "голосовой режим доступен только владельцу", "error": "forbidden"}`. Причина (README): микрофон компьютера один, чужой пользователь не должен его включать.
- Если голос не настроен: 200 с `VOICE_OFF`.
- `volume` и `beep_volume` ограничиваются диапазоном 0..1 (`_clamp_volume`) и записываются в `voice.volume`, `voice.beep_volume`. Голосовой цикл читает их при каждой озвучке (см. `build_voice`), поэтому громкость меняется на лету.
- `enabled` не `None`: вызывается `voice.set_enabled(enabled)`. Иначе возвращается `voice.status()`.
- Ответ идёт через `with_tts`.
- Страница использует этот вызов трёх видов: `{volume}`, `{beep_volume}`, `{enabled}`.

#### `POST /api/listen` (`http/voice.py:87`)

Фраза из режима без рук в браузере. Сервер сам решает по имени, команда это или фон.

- Запрос: `multipart/form-data`: `session_id`, `file`, `played` (число 0..60, по умолчанию 0). `played` — сколько секунд страница проигрывала прошлый ответ.
- Шаги:
  1. Если голос настроен, пользователь — владелец и `voice.status()["enabled"]`, ответ 409 `{"reply": "Джарвис уже слушает микрофон компьютера.", "error": "voice_busy"}`. Проверка стоит до чтения файла. Причина (README): пока серверный цикл слушает микрофон, режим без рук в браузере владельца не работает.
  2. Файл читается с пределом `MAX_AUDIO`, превышение даёт 413.
  3. `service.transcribe(data)` в пуле потоков. Он может бросить `AssistantError` (`stt_empty`, `stt_failed` с кодом 200).
  4. Достаётся `WakeSession` по ключу `(user, session_id)` из `OrderedDict` на 200 записей. Новая сессия создаётся с `voice.wake_word` и `voice.session_silence`, если голос настроен, иначе с «Джарвис» и 5,0 с (`DEFAULT_WAKE_WORD`, `DEFAULT_SESSION_SILENCE`). Это делает `wake_session` (`http/voice.py:75`). Сессия при каждом обращении перемещается в конец; при превышении 200 вытесняется самая старая (`popitem(last=False)`). Комментарий в коде: «сессии в памяти процесса, 200 последних».
  5. `session.on_transcript(text, time.monotonic() - played)`. Вычитание `played` сдвигает «момент речи» назад на время, пока страница проигрывала ответ, чтобы окно разговора считалось от конца ответа.
  6. Результат `None`: `{"heard": false}`. Страница молчит.
  7. Одно имя (`session.name_only`): `{"heard": true, "wake": true, "reply": "Слушаю"}`. Диалог не вызывается.
  8. Иначе вызывается `service.handle_turn(session_id, user, cmd, "voice")`. Затем `session.on_speech(time.monotonic())` продлевает окно. Ответ: тело чата плюс `heard: true`, `transcript` (текст до вычистки имени), `speech: true`.
- `/api/listen` намеренно доступен любому вошедшему пользователю: это режим без рук с микрофоном браузера. Только Джарвис на микрофоне сервера доступен владельцу. Сессии `WakeSession` ключуются парой `(user, session_id)`, чужие ответы недоступны. Если голос не настроен, проверка 409 пропускается.

#### `GET /api/speech/{message_id}` (`http/speech.py:55`)

Озвучка ответа ассистента движком Vosk.

- Ищет сообщение через `service.message(user, id)`. Нет сообщения или роль не `assistant`: 404 `not_found`, «Сообщение не найдено.» Сообщения других пользователей сервис не отдаёт.
- Кэш: `OrderedDict[int, bytes]` на 32 ответа (`SPEECH_CACHE_SIZE`) под `cache_lock`; чтение и запись -- `cached` и `remember`. Попадание в кэш возвращает WAV сразу, без проверок возраста и длины.
- Промах:
  - сообщение старше `SPEECH_MAX_AGE` (по `clock.now()` и `created_at`): 404 `not_found`, «Сообщение слишком старое для озвучки.»;
  - текст длиннее `SPEECH_MAX_CHARS`: 413 `too_long`, «Текст слишком длинный для озвучки.»;
  - `tts` равен `None` или `synthesize` упал: 503 `tts_unavailable`, «Озвучка недоступна.» (исключение логируется).
- Успех: тело `audio/wav`, затем запись в кэш; при размере больше 32 вытесняется самая старая запись.
- Синтез идёт в потоке обработчика. Обработчик синхронный, поэтому блокирует поток из пула FastAPI, а не цикл событий.
- При попадании запись перемещается в конец (`move_to_end` под замком), поэтому вытеснение идёт по давности использования (LRU).

## 3. Голосовой цикл `app/adapters/inbound/voice_loop.py`

Сервер слушает микрофон компьютера, на котором запущен, и реагирует на имя («Джарвис», настройка `WAKE_WORD`). Страницу открывать не нужно: так ассистент работает как Алиса (README, «Голос»). Модуль не знает ни про HTTP, ни про конкретные движки: распознавание, озвучка, запись и проигрывание передаются как объекты и функции. Это позволяет тестам подставлять фейки (`tests/unit/test_voice_loop.py`).

### 3.1 Константы

| Имя | Значение | Смысл |
|---|---|---|
| `RATE` (`:22`) | 16000 | Частота дискретизации, Гц. Формат: моно, 16 бит, little-endian |
| `FRAME_S` (`:24`) | 0.03 | Длина кадра, секунды |
| `FRAME_BYTES` (`:25`) | 960 | `int(RATE * FRAME_S) * 2` байт на кадр |
| `MIN_PHRASE_S` (`:26`) | 0.4 | Минимум озвученной речи в фразе. Короче: фраза отбрасывается |
| `MAX_PHRASE_S` (`:26`) | 30 | Максимальная длина фразы. После неё фраза закрывается принудительно |
| `PREROLL_S` (`:26`) | 0.2 | Сколько тишины перед первым громким кадром добавляется к фразе (7 кадров) |
| `TAIL_S` (`:26`) | 0.15 | Сколько кадров выбрасывается после перезапуска записи (5 кадров) |
| `SPECULATE_S` (`:30`) | 0.5 | После стольких секунд тишины распознавание стартует заранее |
| `MIN_THRESHOLD` (`:31`) | 300 | Нижняя граница порога громкости. Комментарий: на цифровой тишине порог был бы 0 |
| `NOISE_ALPHA` (`:32`) | 0.02 | Коэффициент медленного скользящего среднего уровня шума |
| `DUE_EVERY_S` (`:37`) | 30.0 | Период проверки напоминаний, секунды |

`PREROLL_S` добавляет к фразе кадры тишины перед первым громким кадром. Причины значений констант в коде и README не указаны.

### 3.2 `_Pipe` (`:41`)

Обёртка над подпроцессом записи с интерфейсом файла.

- `__init__(argv)`: запускает `subprocess.Popen(argv, stdout=PIPE, stderr=DEVNULL)`.
- `read(n) -> bytes`: читает из `stdout` процесса. Блокируется, пока не накопится `n` байт или не закончится поток. Короткий результат означает конец потока.
- `close()`: `terminate()`, ожидание 2 с, при таймауте `kill()`.

### 3.3 Функции модуля

`default_recorder() -> _Pipe` (`:58`). Если в системе есть `pw-record`, запускает `pw-record --rate 16000 --channels 1 --format s16 -`. Иначе запускает `arecord -q -f S16_LE -r 16000 -c 1 -t raw -`. Если нет ни того, ни другого, `Popen` бросит исключение, и цикл обработает его как «микрофон недоступен».

`_rms(frame: bytes) -> float` (`:64`). Среднеквадратичная громкость кадра. Лишний нечётный байт отбрасывается, пустой кадр даёт 0.0. Читает 16-битные знаковые числа в порядке байт платформы (`array("h")`).

`_wav(pcm: bytes) -> bytes` (`:69`). Оборачивает сырой PCM в WAV-контейнер: 1 канал, 2 байта на отсчёт, 16 кГц. Такой WAV идёт в распознавание без ffmpeg, это экономит около 110 мс (README).

### 3.4 `VoiceLoop` (`:96`)

Один поток, который читает микрофон, отделяет фразы, распознаёт, вызывает ассистента и озвучивает ответ.

Конструктор `__init__(assistant, stt, tts, user_id, wake_word="Джарвис", phrase_pause=1.0, session_silence=5.0, recorder=default_recorder, player=play_wav, clock=time.monotonic, sounds=False, backoff=(1, 2, 5, 10), debug=False, beeper=None)` (`:97`).

| Параметр | Смысл |
|---|---|
| `assistant` | `AssistantPort`: `handle_turn`, `due_reminders`, `log_voice_error` |
| `stt` | `SpeechToText`: `transcribe(wav_bytes) -> str` |
| `tts` | `TextToSpeech` или `None`. При `None` голосовых ответов нет, сигналы работают |
| `user_id` | Пользователь, которому принадлежат записи, созданные голосом |
| `wake_word` | Имя |
| `phrase_pause` | Секунды тишины, после которых фраза закончена. Пересчитывается в кадры `pause_frames = round(phrase_pause / 0.03)` |
| `session_silence` | Секунды тишины, после которых разговор закрывается. В кадрах: `session_frames` |
| `recorder` | Фабрика потока записи |
| `player` | Проигрыватель WAV для речи |
| `clock` | Источник времени для расписания напоминаний |
| `sounds` | Включает сигналы |
| `backoff` | Паузы между перезапусками после сбоя записи |
| `debug` | Пишет в лог текст принятых фраз |
| `beeper` | Проигрыватель сигналов. По умолчанию равен `player`. Комментарий: сигналы со своей громкостью |

Вычисляемые поля:

- `spec_frames = min(round(SPECULATE_S / FRAME_S), pause_frames - 1)`: после стольких кадров тишины стартует раннее распознавание. Минимум с `pause_frames - 1` гарантирует, что оно стартует раньше конца паузы.
- `_pool = ThreadPoolExecutor(1, thread_name_prefix="voice-stt")`: один поток для раннего распознавания.
- `session = WakeSession(wake_word, math.inf)`: сессия с бесконечным окном. Комментарий: тишину считает цикл по кадрам, а не `WakeSession`.
- `state`, `detail`: текущее состояние и пояснение. Начальное `"off"`, `""`.
- `last_heard`: что услышали последним.
- `_stream`, `_thread`, `_stop`: поток записи, поток цикла, событие остановки.

Состояния `state`: `off`, `waiting`, `listening`, `recognizing`, `thinking`, `speaking`, `error`.

Атрибуты класса `_spoke = False` (`:270`), `_next_due = 0.0` (`:271`), `_beeping = None` (`:289`) — флаг «в этом ходе что-то звучало», время следующей проверки напоминаний, поток сигнала «отправил».

`running` (`:140`). Свойство: поток существует и жив.

`start()` (`:143`). Если цикл уже работает, ничего не делает. Иначе сбрасывает `_stop`, ставит состояние `waiting` и запускает демон-поток `voice-loop` с `_run`.

`stop()` (`:151`). Выставляет `_stop`, закрывает текущий поток записи (это разблокирует `read`), ждёт поток до 5 секунд, ставит состояние `off`.

`_run()` (`:159`). Внешний цикл с перезапуском. Пока не выставлен `_stop`:

1. Сбрасывает `_got_frames`.
2. Создаёт поток записи, ставит `waiting` и вызывает `_listen`. Нормальный выход: причина «перезапуск записи». Исключение (в том числе при создании рекордера): логируется, причина «микрофон недоступен».
3. В `finally` закрывает поток. Комментарий: в том числе рекордер, созданный в гонке со `stop()`.
4. Если остановка запрошена, выходит.
5. Счётчик сбоев `fails` сбрасывается, если были получены кадры, и растёт, если нет.
6. Ставит `state="error"`, `detail=причина` и ждёт `backoff[min(max(fails-1, 0), len(backoff)-1)]` секунд через `_stop.wait` (ожидание прерывается остановкой).

Итог: микрофон, который работает, а затем отключился, перезапускается через 1 с. Микрофон, который не отдаёт кадров, перезапускается всё реже: 1, 2, 5, 10, 10, … секунд.

`_listen(stream)` (`:180`). Основной цикл над кадрами. Читается как оглавление: громкость кадра (`_is_loud`), напоминания между фразами (`_remind_between_phrases`), начало фразы (`_phrase_starts`), продолжение фразы и раннее распознавание (`_extend_phrase`), конец фразы (`_finish_phrase`), перезапуск записи после озвучки (`_restart_stream`). Состояние между кадрами лежит в датаклассе `_Listening` (`:80`): `stream`, `noise`, `threshold`, `pre` (кольцо из 7 кадров), `phrase`, счётчики `voiced`, `quiet`, `idle`, флаг `conversation`, `skip`, `early` (раннее распознавание, в старом коде `spec`).

На каждом кадре:

1. Читает `FRAME_BYTES`. Короткий кадр означает конец потока, функция возвращает управление `_run`.
2. Ставит `_got_frames = True`.
3. Если `skip > 0`, кадр выбрасывается (после озвучки или перезапуска записи).
4. Считает `energy = _rms(frame)`. Если `energy <= threshold`, обновляет уровень шума: первый раз `noise = energy`, дальше `noise += NOISE_ALPHA * (energy - noise)`; порог `threshold = max(MIN_THRESHOLD, noise * NOISE_THRESHOLD_FACTOR)`. Шум подстраивается только по тихим кадрам: речь и щелчок не искажают порог.
5. `loud = energy > threshold`.
6. Напоминания. Если сейчас нет фразы и `clock() >= _next_due`, ставит следующую проверку через `DUE_EVERY_S` и вызывает `_remind()`. Если что-то прозвучало, поток записи пересоздаётся, `skip = round(TAIL_S / FRAME_S)` кадров, переход к следующему кадру. Проверка идёт в паузе между фразами, чтобы не прерывать запись.
7. Вне фразы:
   - тихий кадр: идёт в кольцо `pre`, `idle += 1`. Если разговор открыт и `idle >= session_frames`, разговор закрывается, состояние `waiting`. Переход к следующему кадру;
   - громкий кадр: начинается фраза. В неё копируется кольцо `pre`, счётчики `voiced`, `quiet` обнуляются. Если разговор открыт, состояние `listening`.
8. Кадр добавляется в фразу. Громкий: `voiced += 1`, `quiet = 0`. Тихий: `quiet += 1`.
9. Раннее распознавание. Громкий кадр сбрасывает `early = None`, то есть результат раннего распознавания отбрасывается (задача в пуле завершится, но результат не используется). Тихий кадр при `quiet == spec_frames`, `voiced * 0.03 >= 0.4` и `early is None` отправляет в пул `stt.transcribe(_wav(фраза))`.
10. Конец фразы: `quiet >= pause_frames` или длина фразы не меньше 30 с. Тогда:
    - `pcm` — объединённые кадры, `long_enough = voiced * FRAME_S >= MIN_PHRASE_S`;
    - фраза и `idle` обнуляются;
    - `ready = early`, если фраза закончилась паузой, иначе `None`. При принудительном закрытии по длине фраза уже изменилась с момента раннего запуска, поэтому результат не берётся;
    - если `long_enough`, вызывается `_handle`, он возвращает новое состояние разговора;
    - если `_spoke` и цикл не остановлен, поток записи пересоздаётся, `skip = 5` кадров;
    - состояние `listening`, если разговор открыт, иначе `waiting`.

Зачем раннее распознавание (README, «Голос»): распознавание начинается после 0,5 с тишины, не дожидаясь конца паузы. Если человек продолжил, результат выбрасывается. Если замолчал, текст готов к концу паузы, и 0,2 с распознавания не добавляются к ожиданию.

Зачем пересоздавать запись после озвучки (README, «Голос», комментарий в коде): озвучка блокирующая, пока она идёт, в трубе копится только эхо. Новый процесс записи отсекает эхо, а живой ответ пользователя, сказанный сразу после вопроса, не теряется. Раньше кадры отбрасывались по длительности озвучки, и вместе с эхом терялся ответ пользователя.

Зачем 0,15 с (`skip`): в README указано «запускается заново через 0,15 с»; причина конкретного значения не приведена.

Фоновая речь вне разговора: фраза без имени игнорируется и не попадает в чат.

`_remind() -> bool` (`:273`). Произносит наступившие напоминания. Сбрасывает `_spoke`, вызывает `assistant.due_reminders(user_id)`. Исключение логируется (`due reminders failed`), результат `False`. Для каждого напоминания: сигнал `start`, затем речь «Напоминание: <название>». Если что-то прозвучало и цикл не остановлен, состояние `waiting`. Возвращает `_spoke`. Запись в чат делает сервис, а не цикл (docstring). Если `sounds=False` и `tts is None`, ничего не звучит, и функция вернёт `False`.

Почему напоминания выбирает цикл (README): наступившие напоминания произносит Джарвис, если он включён, а страница их только показывает. `/api/reminders/due` для владельца при включённом голосе возвращает `[]` по этой же причине.

`_beep(name, wait=True)` (`:291`). Проигрывает сигнал `sound(name)` через `beeper`. Не делает ничего, если `sounds=False` или цикл остановлен. Ставит `_spoke = True`. Исключения проигрывателя логируются («signal failed»). При `wait=True` играет в текущем потоке. При `wait=False` играет в отдельном демон-потоке, ссылка на него хранится в `_beeping`. Docstring: сигнал играет, пока ассистент думает, и не задерживает ответ. README: сигнал «отправлено» раньше задерживал ответ на 0,2 с.

`_say(text, error=False, state="speaking")` (`:309`). Озвучивает текст.

1. При `error` сначала играет сигнал `error`.
2. Если `tts is None` или цикл остановлен, выходит.
3. `tts.synthesize(text)`; затем, если есть поток `_beeping`, ждёт его до 2 с («сигнал "отправил" доигрывает до начала речи»).
4. Ставит `state` и `_spoke = True`, вызывает `player(wav)` (блокирующе).
5. Любое исключение логируется («voice reply failed»), цикл продолжает работу.

`_handle(pcm, conversation, ready=None) -> bool` (`:324`). Обрабатывает одну фразу и возвращает, открыт ли разговор после неё.

1. Сбрасывает `_spoke`, ставит `recognizing`.
2. Текст берётся из `ready.result()` (раннее распознавание) или из `stt.transcribe(_wav(pcm))`.
3. Сбой распознавания: предупреждение в лог, состояние `error`. Если разговор открыт, сообщение (`e.user_message` для `AssistantError`, иначе «Не удалось распознать речь.») записывается в чат через `assistant.log_voice_error` и озвучивается как ошибка. Вне разговора фоновая речь не должна засорять чат, поэтому ошибка молчит. Возвращает прежнее значение `conversation`.
4. `session.open = conversation`, затем `session.on_transcript(text, 0)`. Результат `None` — фраза без имени вне разговора. Очистка слов-паразитов и сравнение с именем выполняются внутри `WakeSession`.
5. Если распознанный текст не пуст: считает `named` (в начале фразы есть имя) и `used` (фраза принята). Пишет в лог строку `voice heard: wake=yes|session|no chars=N`. Текст добавляется в лог только при `debug` и `used`. В `last_heard` попадает `{"used": true, "text": ..., "words": N}` для принятой фразы и `{"used": false, "text": null, "words": N}` для фоновой. Текст фоновой речи не хранится и не логируется (README: фоновые разговоры у микрофона приватны). Если распознан пустой текст, `last_heard` не меняется.
6. `text is None`: возвращает `conversation`.
7. Одно имя (`session.name_only`): состояние `listening`, сигнал `start`, речь «Слушаю», возвращает `True`.
8. Иначе состояние `thinking`, сигнал `sent` без ожидания, затем `assistant.handle_turn("voice", user_id, text, source="voice").reply` озвучивается. Идентификатор сессии диалога — строка `"voice"`.
9. `AssistantError`: состояние `error`, озвучивается `e.user_message` как ошибка (сервис уже записал её в чат). Прочее исключение: лог, речь «Что-то пошло не так.».
10. Во всех путях после распознавания возвращается `True`: разговор остаётся открытым даже после ошибки.

### 3.5 `VoiceControl` (`:385`)

Включатель цикла. Docstring: Vosk грузится при первом включении. Тяжёлая загрузка идёт в отдельном потоке, чтобы HTTP-запрос не висел.

Конструктор `__init__(factory, wake_word, has_recorder=<есть ли pw-record или arecord>, owner="default", volume=0.8, beep_volume=0.5, phrase_pause=1.0, session_silence=5.0)` (`:388`).

| Параметр | Смысл |
|---|---|
| `factory` | Создаёт `VoiceLoop` (вызывается в потоке загрузки) |
| `wake_word` | Имя для показа на странице |
| `has_recorder` | Проверка наличия программы записи |
| `owner` | Единственный пользователь, который может управлять режимом |
| `volume`, `beep_volume` | Громкость речи и сигналов. Изменяются из `/api/voice` |
| `phrase_pause`, `session_silence` | Отдаются странице для режима без рук |

Поля: `_loop`, `_broken` (текст сбоя), `_starter` (поток загрузки), `wait = 0.3` (сколько POST ждёт загрузки, прежде чем ответить `loading`), `_lock`.

`status() -> dict` (`:413`). Состояние для страницы.

- `off` — причина недоступности: `_broken` или, если нет программы записи, «микрофон не найден (нужен pw-record или arecord)». Пустая строка, если всё в порядке.
- `on` — цикл создан и работает; `loading` — поток загрузки жив.
- `state`: `loading`, иначе состояние цикла (если он работает), иначе `error` при `_broken`, иначе `off`.
- `detail`: «загружаю голос…» при загрузке, иначе `detail` цикла, иначе причина `off`.
- Ответ: `enabled` (`on` или `loading`), `state`, `detail`, `wake_word`, `available` (`not off`), `last_heard`, `volume`, `beep_volume`, `phrase_pause`, `session_silence`.

`_init()` (`:439`). Выполняется в потоке `voice-init`. Создаёт `VoiceLoop` через `factory` (если его ещё нет) и запускает. Исключение: лог и `_broken = "не удалось загрузить голос Vosk"`. После сбоя `_loop` остаётся `None`, следующее включение снова вызовет фабрику.

`set_enabled(on: bool) -> dict` (`:447`). Включает или выключает цикл.

- Под `_lock`: при `on` сбрасывает `_broken` (новая попытка загрузки). Если режим доступен и поток загрузки не работает, запускает его.
- При `on=False`: ждёт конца загрузки (`join` без отмены, отмены нет) и останавливает цикл.
- Вне блокировки при `on` ждёт поток загрузки до `wait` секунд. Возвращает `status()`. Если за 0,3 с загрузка не закончилась, ответ содержит состояние `loading`, и страница дальше следит за ним опросом `/api/voice`.
- Если `on` и режим недоступен (нет программы записи), ничего не запускается; в статусе `available: false`.

`stop()` (`:464`). Эквивалент `set_enabled(False)`. Вызывается при остановке приложения.

## 4. Веб-страница `app/adapters/inbound/static/index.html`

Один файл: разметка, стили и скрипт в одной функции-обёртке (`index.html:230`). Внешних библиотек нет. Единственный внешний ресурс — шрифт Onest с Google Fonts. Тема светлая или тёмная по настройке системы (`prefers-color-scheme`). Иконки — встроенные SVG-символы. При ширине до 819 пикселей боковая панель превращается в выдвижной лист с кнопкой «План».

Сервер отдаёт файл как статику (`http/__init__.py:73`). Страница состоит из шапки (имя, переключатель «Джарвис» с состоянием, пользователь, календарь, «План», настройки, «Выйти»), области чата, формы ввода с кнопкой микрофона, боковой панели «Сегодня»/«Завтра» и экрана входа.

### 4.1 Состояние и хранилище

Ползунок `bvol` (громкость сигнала) отправляет `{beep_volume}`. Переключатель `speak` останавливает проигрыватель и браузерную озвучку при выключении.

Чат.

- `add(role, t, o)` (`:423`). Добавляет сообщение. Убирает подсказку. Принимает карточки `o.items`, иконку, примечание `o.note`, класс. Для ответов ассистента вызывает `planSoon()`. Прокручивает чат вниз.
- `busy(b)` (`:435`). Блокирует кнопку отправки и показывает индикатор набора.
- `post(url, opts, spoken)` (`:440`). Отправка запроса в чат: показывает индикатор, на 401 вызывает `showLogin`. Запоминает `message_ids` в `seen` и увеличивает `gen`. Показывает `transcript` (как реплику пользователя с иконкой голоса), ответ с карточками и пометкой «жду ответа» при `clarify`. Ответ с `error` или статусом не 2xx получает класс ошибки. Если `spoken` и есть `speak_id`, запрашивает озвучку. Сетевой сбой: «Нет связи с сервером».
- `sendText(t)` (`:455`). Показывает реплику пользователя, очищает поле, шлёт `POST /api/message`. Enter отправляет, Shift+Enter переносит строку, ввод через IME не отправляется. Кнопки-подсказки отправляют свой текст.

Опрос истории.

- `history(first)` (`:587`). Запрашивает `/api/history?after=<lastId>`; при первом вызове добавляет `limit=50`. Пропускает вызов, если идёт отправка или запись (кроме первого). Если за время запроса завершилась отправка (`gen` изменился), ответ отбрасывается: id собственных сообщений ещё не в `seen`. Каждое сообщение показывается один раз. Префикс `⏰ ` в тексте убирается. Ответ ассистента, начинающийся с «Напоминание: », оформляется как напоминание с иконкой колокольчика. Реплики пользователя с `source == voice` получают иконку голоса.
- Запускается раз в 1,5 с вместе с `voice()`.

Запись одного сообщения.

- `mic.onclick` (`:467`). Если у сервера есть имя (`hf.cfg.wake_word`) и серверный режим не занят, кнопка переключает режим без рук (см. 4.3). Иначе: первое нажатие запрашивает микрофон, создаёт `MediaRecorder` (формат `audio/webm;codecs=opus`, если поддерживается), запускает запись с таймером; второе нажатие или 30 секунд останавливают запись. После остановки блоб уходит в `POST /api/audio` с `spoken = true` (ответ озвучивается). Нет доступа к микрофону: «Нужен доступ к микрофону (HTTPS или localhost)». Если `MediaDevices` или `MediaRecorder` не поддерживаются, кнопка отключена.
- `stopRec()` (`:466`). Останавливает запись, если она идёт.
- Отмена (`cancelled`): `showLogin` ставит флаг, и записанное не отправляется.

### 4.3 Режим без рук

Страница держит микрофон браузера открытым и сама решает, где начало и конец фразы, по энергии звука. Каждая фраза уходит на `POST /api/listen`, а имя ищет сервер (README: сервер решает по имени).

Состояние `hf`: `on`, `busy` (серверный цикл занят), `cfg` (конфигурация голоса от сервера), `posting`, `playing`, `rec`, `open`, `hold`, `played`, `pstart`, `shown`, `wake`, а также `stream`, `ctx`, `an` (анализатор), `buf`, `thr`, `noise`, `timer`.

| Функция | Строка | Назначение |
|---|---|---|
| `hfWin()` | 501 | Окно разговора в мс: `session_silence * 1000` |
| `hfPlay(on)` | 502 | Отмечает начало и конец проигрывания. По окончании копит `played` (секунды), ставит `hold = now + 300 мс` и продлевает `open` на окно разговора |
| `hfShow()` | 510 | Показывает состояние: `speak`, `listen`, `think`, `wait` и подпись («отвечаю», «слушаю», «думаю», «жду «<имя>»») |
| `hfEnd(keep)` | 518 | Останавливает запись фразы; `keep` определяет, отправлять ли её |
| `hfBegin()` | 519 | Создаёт `MediaRecorder` на текущем потоке и обнуляет счётчики фразы |
| `hfTick()` | 527 | Один такт анализа, каждые 30 мс |
| `hfSend(blob)` | 543 | Отправка фразы и показ ответа |
| `hfStart()` | 563 | Включает режим |
| `hfStop(keepPref)` | 578 | Выключает режим |

`hfStart` запрашивает микрофон с `echoCancellation` и `noiseSuppression`, создаёт `AudioContext` и `AnalyserNode` (`fftSize` 1024). Начальный порог 0,01. Таймер `hfTick` каждые 30 мс. Флаг `hf` в `localStorage` ставится в `1`. Ошибка доступа: флаг в `0`, сообщение, режим не включается.

`hfTick` на каждом такте:

1. Считает среднеквадратичное значение окна.
2. Если идёт проигрывание, отправка или время меньше `hold`, прерывает запись без отправки. Страница не слышит сама себя.
3. Порог подстраивается по тихим кадрам: `noise` — скользящее среднее с коэффициентом 0,02, `thr = max(0.01, noise * 3)`. Те же 0,02 и множитель 3, что у серверного цикла; нижняя граница другая (0,01 для сигнала в диапазоне −1..1 против 300 для 16-битных отсчётов).
4. Индикатор уровня показывает `e / thr`.
5. Запись начинается с первого громкого кадра. Комментарий в коде: первые ~30 мс фразы теряются; если имена будут обрезаться, держать записывающий поток постоянно.
6. Накапливает громкое и тихое время и общую длину. Фраза закрывается при тишине не меньше `phrase_pause` секунд (из `cfg`) или длине 30 с. Фраза отправляется, только если громкого времени не меньше 400 мс.

`hfSend`:

- Тело: `session_id`, `played` (до 60 секунд, два знака; затем счётчик обнуляется), `file`.
- 401: `showLogin`. 409: пересчитать состояние голоса (`voice()`), что включит `hfStop(true)` и покажет «Джарвис уже слушает микрофон компьютера».
- Нет `heard` и нет `message_ids`: тишина (фон или сбой распознавания).
- Одно имя (`wake`): озвучивает «Слушаю» через `speakText`.
- Иначе показывает `transcript` и ответ, а если `speech` и есть id и ответ, озвучивает последний через `speakServer`.
- Окно разговора `open` продлевается. В `finally` снимается `posting` и ставится `hold` на 300 мс.

`played` передаёт серверу, сколько страница проигрывала прошлый ответ (комментарий в `/api/listen`). `hold` 300 мс не даёт записывать сразу после проигрывания и отправки. Причина значения в коде не указана.

`hfStop(keepPref)` останавливает таймер, запись, дорожки микрофона и `AudioContext`. Без `keepPref` флаг `hf` в `localStorage` становится `0` (пользователь выключил режим). С `keepPref` настройка остаётся: так режим вернётся, когда серверный цикл освободит микрофон. Затем запрашивает состояние голоса.

### 4.4 Состояние голосового режима

- `showVoice(v)` (`:603`). Применяет ответ `/api/voice`. Запоминает конфигурацию (`hf.cfg`), если есть имя. Вычисляет `hf.busy`: сервер включён и доступен. Блокирует кнопку микрофона при занятом сервере или неподдерживаемом браузере. Показывает заметку «Джарвис уже слушает микрофон компьютера». Если режим без рук работал, останавливает его. Обновляет точку состояния, ползунки громкости (кроме того, который пользователь сейчас двигает), строку «услышал: …» или «услышал фразу без имени», переключатель, значок загрузки и подпись состояния.
- `voice()` (`:619`). Запрашивает `/api/voice` и вызывает `showVoice`.
- Обработчик переключателя «Джарвис» (`:622`). Отправляет `{enabled}`, показывает ответ; при ошибке обновляет состояние.
- Слова состояний: `listening` — «слушаю», `recognizing` — «распознаю», `thinking` — «думаю», `speaking` — «отвечаю», `off` — «выключен» (`WORDS`, `:602`). Для `waiting` — «жду «<имя>»». Для ошибки, загрузки и недоступности показывается `detail`.

### 4.5 Боковая панель «Сегодня» и «Завтра»

Правая колонка показывает открытые записи на два дня по Москве. Записи можно добавлять, менять и удалять; чат при этом не затрагивается.

- `plan()` (`:401`). Запрашивает `/api/items?from=<сегодня>&to=<завтра>&status=open`. Не перерисовывает панель, пока открыта форма (форму не стирают). Счётчик `planN` отбрасывает устаревшие ответы. Записи группируются по дню (`starts_at` по Москве или `due_date`), сортируются по времени; записи без времени идут в конце. Пустой день: «Ничего не запланировано». Строка — кнопка: Enter, Пробел и щелчок открывают форму правки. На 401 вызывает `showLogin`.
- `planSoon()` (`:327`). Откладывает `plan()` на 400 мс (сжимает серию вызовов). Вызывается после каждого ответа ассистента.
- `pform(it, day)` (`:341`). Строит форму: название (до 200 символов), три кнопки вида в порядке «задача, напоминание, встреча», дата, время (необязательно), длительность (только для встречи). Список длительностей `DUR` — 15, 30, 45, 60, 90, 120, 180 минут плюс текущая длительность записи, если её нет в списке. Для повторяющейся записи (`rrule`) дата заблокирована и не отправляется: «Дату серии здесь не меняют». Кнопки «Сохранить», «Отмена» и (для существующей записи) «Удалить» с подтверждением «Да/Нет». Проверки на странице: название не пусто, дата указана. Escape закрывает форму, Enter в поле названия сохраняет.
  - Тело запроса: `kind`, `title`, `time` (`null`, если пусто), `duration_minutes` (число только для встречи с выбранной длительностью, иначе `null`), `date` (если поле не заблокировано).
  - Новая запись: `POST /api/items`. Существующая: `PATCH /api/items/<id>`. Поскольку `time` и `duration_minutes` отправляются всегда, `null` снимает время и длительность.
- `pcall(method, url, body)` (`:331`). Вызов API формы. Возвращает `null` при успехе и текст ошибки при неудаче: на 401 вызывает `showLogin`; иначе берёт `reply` из тела или «Ошибка сервера (<код>)»; сетевой сбой — «Нет связи с сервером».
- `openForm(box, it, day, row)` (`:394`). Открывает одну форму за раз; если форма уже открыта, ставит в неё фокус. Правка заменяет строку записи, добавление вставляется в начало списка дня.
- Кнопки «+» у каждого дня открывают форму добавления на сегодня или завтра (`:400`).

### 4.6 Напоминания и запуск

- `poll()` (`:630`). `POST /api/reminders/due`. Для каждой записи произносит «Напоминание: <название>» браузерным голосом (`say`). В чат запись не добавляет: сообщение о напоминании записал сервис, оно придёт через `history`. Вызывается сразу при запуске и каждые 30 секунд. На 401 — `showLogin`. Если включён серверный Джарвис владельца, сервер возвращает пустой список.
- Стартовая функция (`:639`). Запрашивает `/api/me`. 401: экран входа. Сбой запроса: показывает чат с сообщением «Не удалось проверить вход. Обновите страницу.» При успехе: показывает имя, признак подключённого календаря («Календарь подключён»), кнопку «Выйти» (кроме гостя). Затем показывает чат, форму и панель, загружает историю, состояние голоса, при флаге `hf` в `localStorage` и свободном сервере включает режим без рук. Запускает опрос `history()` и `voice()` каждые 1,5 с и опрос напоминаний.

## 6. Сборка `app/bootstrap.py`

Модуль — корень композиции: единственное место, которое знает все конкретные классы и соединяет их. Остальные слои зависят от портов.

### 6.1 `build_calendar(settings, db)` (`bootstrap.py:35`)

Возвращает пару `(CalendarLinks, CalendarSync)` или `(None, None)`.

- Выгрузка включена, если задан `token_encryption_key` и вход не отключён. Привязка календаря создаётся при входе через Яндекс (`build_auth.on_login`), без входа привязок нет.
- Ключ проверяется конструктором `Fernet`. Неверный ключ: `RuntimeError("TOKEN_ENCRYPTION_KEY is invalid")`. Исходное исключение подавлено (`from None`).
- Создаёт `SqliteCalendarLinks(db, ключ)` и `YandexCalendarSync(links, client_id, client_secret, SystemClock())`.

Токены календаря шифруются (Fernet, ключ только в `.env`), потому что хранятся долго и дают доступ к календарю (README).

### 6.2 `LazyTTS` (`bootstrap.py:48`)

Один движок Vosk на цикл Джарвиса и страницу (docstring). Модель грузится при первой озвучке или при прогреве.

- `__init__(s)`: хранит настройки, пустой движок, блокировку и флаг `_warm`.
- `ready` (`:58`): свойство, `True`, когда движок загружен. `http/voice.py` по нему строит `tts_ready`.
- `warmup()` (`:61`): запускает загрузку в демон-потоке `tts-warmup`. Повторный вызов ничего не делает. Флаг `_warm` ставится до запуска потока, поэтому после сбоя прогрев не повторяется. Сбой логируется (`tts warmup failed`) и виден при озвучке или включении Джарвиса. Причина (комментарий в `main.py`): модель грузится около минуты, старт не блокируется.
- `load()` (`:75`): под блокировкой загружает `VoskTTS.load(tts_model, tts_speaker)`, если он ещё не загружен, и возвращает движок. Импорт `vosk_tts` отложен до первой загрузки (комментарий: тяжёлый импорт). Блокировка делает так, что переключатель и `/api/speech` ждут ту же загрузку, а не запускают вторую.
- `synthesize(text) -> bytes` (`:83`): `load().synthesize(text)`. Комментарий: движок сам сериализует вызовы.

### 6.3 `build_voice(s, assistant, tts=None) -> VoiceControl` (`bootstrap.py:87`)

Создаёт `VoiceControl`. Если `tts` не передан, создаёт свой `LazyTTS`.

Внутренняя функция `make()` (`:96`) создаёт `VoiceLoop`. Сначала вызывает `tts.load()` (комментарий: сбой загрузки модели виден при включении), затем собирает цикл из `assistant`, `assistant.stt`, `tts`, `voice_user_id`, `wake_word`, `voice_phrase_pause`, `voice_session_silence`, `voice_sounds`, `voice_debug`. Проигрыватели получают громкость из `ctl.volume` и `ctl.beep_volume` при каждом вызове, поэтому перемещение ползунка действует сразу. `ctl` — это объект `VoiceControl`, созданный строкой ниже (`:112`) с `owner=voice_user_id`, начальными громкостями и параметрами паузы.

### 6.4 `build_auth(settings, db, embedder=None, links=None) -> AuthService | None` (`bootstrap.py:124`)

- `auth_disabled`: возвращает `None`.
- Демо-посев: при `demo_seed` создаётся хук, который после первого входа нового пользователя импортирует `data/voice_assistant_events_1000.csv` этому пользователю через `scripts.import_csv.import_csv`. Импорт `scripts` отложен до вызова хука.
- Провайдер входа: `YandexIdProvider(client_id, client_secret, redirect_uri)`.
- Если есть `links`, создаётся `on_login(user, p)`: при наличии `p.email` сохраняется `CalendarLink` с токенами и сроком (`expires_in`, а если его нет, 365 суток). Если почты нет, пишет предупреждение «calendar not linked ... no email from Yandex (grant login:email)»: для календаря у приложения Яндекса нужно право `login:email`.
- Возвращает `AuthService(idp, SqliteUserStore(db), SystemClock(), hook, on_login)`.

### 6.5 `build(settings, stt=None, db=None, embedder=None, calendar=None) -> AssistantService` (`bootstrap.py:165`)

Собирает сервис ассистента.

1. База и эмбеддер создаются, если не переданы (`Database(db_path)`, `E5Embedder.load()`).
2. `SqliteItemRepository(db, embedder, clock)` и `repo.embed_missing()`: дописывает вектора записям, у которых их ещё нет.
3. Два клиента GigaChat: `pro` и `lite` (`make_client` с закреплёнными сертификатами `certs_path`).
4. `SqliteVectorIndex(db, embedder)` для поиска.
5. Словарь обработчиков намерений: `CreateTask`, `CreateMeeting`, `Unknown`, `Confirm`, `ListItems`, `SearchItems`, `CompleteItem`, `UpdateItem`, `DeleteItem`. Календарь передаётся создающим, правящим и удаляющим обработчикам.
6. Распознавание речи: `GigaAMSpeechToText.load(stt_model)`, если `stt` не передан (тесты подставляют фейк).
7. Результат: `AssistantService(GigaChatIntentParser(pro, split_client=lite), stt, repo, SqliteDialogStore(db, clock.now, dialog_pending_ttl), clock, handlers, SqliteMessageLog(db, clock), calendar)`.

Лёгкая модель делит составную фразу на команды; основная модель разбирает команды (README, `GIGACHAT_MODEL_LITE`).

## 7. Фабрика `app/main.py`

`create() -> FastAPI` (`main.py:13`). Запуск: `uvicorn --factory app.main:create`. Импорт модуля ничего не загружает: тяжёлые модели создаются только при вызове `create` (docstring).

11. Если `tts_preload`: `tts.warmup()`. Комментарий: модель грузится около минуты, старт не блокируется; переключатель и `/api/speech` ждут ту же загрузку.

## 8. Скрипты `scripts/`

### 8.1 `scripts/import_csv.py`

Запуск: `python -m scripts.import_csv [path] [--db PATH] [--if-empty]`.

`kind_for(text) -> ItemKind` (`import_csv.py:16`). Вид записи по первому слову названия (в нижнем регистре): «встреча», «созвон», «демо», а также любое название, где есть «планёрк» или «планерк», дают встречу. «напомнить» даёт напоминание. Остальное — задача. Пустая строка даёт задачу. Правило описано в README, «Данные».

`import_csv(repo, db, path, user_id="default", now=None) -> int` (`import_csv.py:26`). Загружает CSV, возвращает число записей.

- `now` по умолчанию `SystemClock().now()` (порт `Clock`). Параметр нужен для проверки поведения в тестах.
- Сначала в одной транзакции удаляет прежние импортированные записи пользователя (`source='import'`) вместе с векторами из `items_vec`. Поэтому импорт идемпотентен: повторный запуск не плодит дубли (README).
- Читает файл в кодировке `utf-8-sig`, колонки `date`, `time`, `text` (в спецификации ещё `id`; значение `id` не используется).
- Для каждой строки создаёт запись с видом, названием, `source="import"`, `starts_at` (дата + время по MSK) и `due_date`. Вектор не считается на каждой записи (`embed=False`).
- Напоминания в прошлом получают `notified_at = starts_at`. Комментарий: прошедшие напоминания не должны сработать разом при первом открытии.
- После цикла один вызов `repo.embed_missing()` считает вектора пачкой.

`main()` (`import_csv.py:59`). Читает `.env`, разбирает аргументы: `path` (по умолчанию `data/voice_assistant_events_1000.csv`), `--db` (по умолчанию `DB_PATH` из окружения или `./assistant.db`), `--if-empty`. С `--if-empty` пропускает импорт, если в таблице `items` есть хотя бы одна строка (любого пользователя), и печатает «items not empty, skip import». Иначе импортирует пользователю `default` и печатает «Imported N items».

Импорт кладёт записи пользователю `default`; при включённом входе вошедший пользователь их не видит (README). Для демо со входом служит `DEMO_SEED=1`.

### 8.2 `scripts/pin_certs.py`

Запуск: `python -m scripts.pin_certs`. Обновляет `certs/gigachat.pem` с двумя листовыми сертификатами серверов GigaChat.

`HOSTS` (`pin_certs.py:4`). `ngw.devices.sberbank.ru:9443` (получение токена) и `gigachat.devices.sberbank.ru:443` (API).

`main(path="certs/gigachat.pem")` (`pin_certs.py:7`). Для каждого узла получает сертификат в PEM (`ssl.get_server_certificate`), печатает владельца (`subject`), издателя (`issuer`), срок (`notAfter`) и отпечаток SHA-256 от DER-формы. Затем перезаписывает файл всеми сертификатами подряд и просит сверить отпечатки командой `openssl s_client ...`. Каталог `certs/` должен существовать. Сертификат запрашивается без проверки цепочки, поэтому отпечатки нужно сверять вручную.

`_decode(pem) -> dict` (`pin_certs.py:33`). Разбирает PEM во временном файле через `ssl._ssl._test_decode_cert` и удаляет файл. Комментарий в коде: приватный API CPython, стабилен годами; если сломается, использовать `cryptography`.

Зачем (README, «TLS и сертификаты»): серверы GigaChat подписаны «Russian Trusted Sub CA» Минцифры. Корневой сертификат Минцифры не устанавливается: он дал бы доверие ко всем сайтам, которые он подписывает. `verify_ssl_certs=False` не используется: отключённая проверка открыла бы подмену ответа. Вместо этого два листовых сертификата считаются доверенными только в `SSLContext` клиента GigaChat. Сертификаты истекают 30.06.2027 и 13.07.2027; после перевыпуска нужно запустить скрипт.

### 9.3 `docker-compose.voice.yml`

Накладывается на основной файл: `docker compose -f docker-compose.yml -f docker-compose.voice.yml up --build`. Только Linux-хост со звуковым сервером PulseAudio или PipeWire.

- `PULSE_SERVER: unix:/run/pulse/native` — адрес звукового сервера внутри контейнера.
- `VOICE_ENABLED: ${VOICE_ENABLED:-1}` — режим включается сразу; значение можно переопределить с хоста.

Отдельный файл нужен, чтобы базовый `docker-compose.yml` запускался и там, где сокета нет (macOS, Windows) — комментарий в файле. Со входом через Яндекс нужно задать `VOICE_USER_ID` своим id, иначе Джарвис пишет записи пользователю `default` (README).

### 9.4 `docker/asound.conf`

```
pcm.!default { type pulse }
ctl.!default { type pulse }
```

Направляет устройства ALSA по умолчанию в плагин pulse. Тогда `arecord` и `aplay` в контейнере идут в звуковой сервер хоста через сокет `PULSE_SERVER` (комментарий в файле). В образе нет `pw-record`, поэтому `default_recorder` выбирает `arecord`.

## 11. Расхождения и неясные места

1. `certs_path` нельзя задать переменной окружения: поле есть в `Settings`, но `load_settings` его не читает.
2. Причины значений `SPEECH_MAX_AGE` (10 минут), `SPEECH_MAX_CHARS` (500), `hold` 300 мс, `skip` 0,15 с, `MIN_PHRASE_S`, `PREROLL_S` в коде и README не названы.
3. Нечисловое значение переменной окружения для чисел даёт необработанный `ValueError` при старте.
4. В режиме без входа `request.state.user_id` не заполняется, и лог ошибок пишет `user=None`.
